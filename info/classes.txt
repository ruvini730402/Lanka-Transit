=== DATABASE TABLE STRUCTURES (Current Schema) ===

User Table
- ID: int (PK, AUTO_INCREMENT)
- Name: varchar(100) NOT NULL
- Email: varchar(60) NOT NULL UNIQUE
- PasswordHash: varchar(255) NOT NULL
- PhoneNumber: varchar(10) NOT NULL
- Role: enum('administrator','guest user','registered user') DEFAULT 'registered user'
- RegistrationDate: timestamp DEFAULT CURRENT_TIMESTAMP

Admin Table
- ID: int (PK, AUTO_INCREMENT)
- Email: varchar(60) NOT NULL UNIQUE
- PasswordHash: varchar(255) NOT NULL
- Name: varchar(100) NOT NULL
- PhoneNumber: varchar(10) NOT NULL

Booking Table
- ID: int (PK, AUTO_INCREMENT)
- UserId: int (FK to User.ID, NULLABLE for guest bookings)
- BusID: int (FK to Bus.ID) NOT NULL
- SeatNumber: varchar(6) NOT NULL
- PhoneNumber: varchar(10) NOT NULL
- Fare: decimal(10,2) NOT NULL
- Status: enum('confirmed','cancelled','completed') DEFAULT 'confirmed'
- BookingTime: timestamp DEFAULT CURRENT_TIMESTAMP

Bus Table
- ID: int (PK, AUTO_INCREMENT)
- RouteId: int (FK to Route.ID, NULLABLE)
- AdminId: int (FK to Admin.ID, NULLABLE)
- BusNumber: varchar(20) NOT NULL UNIQUE
- Capacity: int NOT NULL
- LastUpdate: date DEFAULT CURRENT_DATE

Route Table
- ID: int (PK, AUTO_INCREMENT)
- Origin: varchar(50) NOT NULL
- Destination: varchar(50) NOT NULL
- Stops: text (NULLABLE)
-- Active Routes: 1='Badulla to Matara', 2='Matara to Badulla'

Payment Table
- ID: int (PK, AUTO_INCREMENT)
- BookingId: int (FK to Booking.ID) NOT NULL
- PaymentMethod: varchar(50) DEFAULT 'Demo Payment'
- Status: enum('success','failed','pending') DEFAULT 'pending'
- Amount: decimal(10,2) NOT NULL
- PaymentDate: timestamp DEFAULT CURRENT_TIMESTAMP
- TransactionId: varchar(100) UNIQUE

Incident Table
- ID: int (PK, AUTO_INCREMENT)
- UserId: int (FK to User.ID, NULLABLE)
- AdminId: int (FK to Admin.ID, NULLABLE)
- BookingId: int (FK to Booking.ID, NULLABLE)
- RouteId: int (FK to Route.ID, NULLABLE)
- Description: text NOT NULL
- Status: enum('submitted','in progress','resolved') DEFAULT 'submitted'
- ReportedDate: date DEFAULT CURRENT_DATE
- ResolvedDate: date (NULLABLE)

Feedback Table
- ID: int (PK, AUTO_INCREMENT)
- UserId: int (FK to User.ID, NULLABLE)
- BusId: int (FK to Bus.ID, NULLABLE)
- Comment: text
- Rating: int (1-5)
- CreatedDate: date DEFAULT CURRENT_DATE

Seat Table
- ID: int (PK, AUTO_INCREMENT)
- BusID: int (FK to Bus.ID) NOT NULL
- SeatNumber: varchar(6) NOT NULL
- Status: enum('available','booked') DEFAULT 'available'
- GenderPreference: enum('male','female','general') DEFAULT 'general'
- IsLadySeat: boolean DEFAULT FALSE

Announcements Table
- ID: int (PK, AUTO_INCREMENT)
- title: varchar(200) NOT NULL
- message: text NOT NULL
- created_at: timestamp DEFAULT CURRENT_TIMESTAMP
- updated_at: timestamp DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

=== EXTENDED SCHEMA TABLES ===

User_2 Table (Password Reset Extension)
- user_id: int (PK, FK to User.ID)
- reset_token: varchar(255) (NULLABLE)
- token_expiry: datetime (NULLABLE)
- created_at: timestamp DEFAULT CURRENT_TIMESTAMP
- updated_at: timestamp DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Booking_2 Table (Gender Tracking Extension)
- booking_id: int (PK, FK to Booking.ID)
- gender: enum('male','female','undisclosed') DEFAULT 'undisclosed'
- created_at: timestamp DEFAULT CURRENT_TIMESTAMP
- updated_at: timestamp DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Admin_2 Table (Admin Metadata Extension)
- admin_id: int (PK, FK to Admin.ID)
- created_at: timestamp DEFAULT CURRENT_TIMESTAMP
- updated_at: timestamp DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

=== CURRENT WORKFLOW PATTERNS ===

**User Registration/Login Flow:**
1. User registers via auth/register.php
2. Login through auth/login.php with session creation
3. Access user dashboard and booking features
4. Logout via auth/Logout.php

**Booking Process Flow:**
1. Search buses via pages/search.php
2. Select bus and view details (pages/bus-details.php)
3. Choose seats in seatbooking interface (pages/seatbooking.php)
4. Process payment (pages/payment.php)
5. Confirm booking and generate ticket (pages/confirmation.php)
6. Download PDF ticket (pages/ticket_pdf.php)

**Incident Management Flow:**
1. Users report incidents via pages/incidents.php
2. Incidents stored with 'submitted' status in database
3. Admins view and manage via pages/manage_incidents.php
4. Status updates processed through pages/update_incidents.php
5. Resolved incidents get ResolvedDate timestamp

**Admin Management Flow:**
1. Admin login through dedicated admin interface
2. Access admin dashboard (Admin/admin.html)
3. Manage buses, users, bookings, and incidents
4. Create/update system announcements
5. Monitor feedback and system activity

=== DATABASE RELATIONSHIPS (Active) ===

- User (1) ←→ (0..n) Booking (Users can make multiple bookings)
- User (1) ←→ (0..1) User_2 (Password reset data)
- Booking (1) ←→ (1) Payment (Each booking has payment record)
- Booking (1) ←→ (0..1) Booking_2 (Gender tracking)
- Booking (n) ←→ (1) Bus (Multiple bookings per bus)
- Bus (1) ←→ (0..n) Seat (Each bus has multiple seats)
- User (1) ←→ (0..n) Feedback (Users submit feedback)
- User (1) ←→ (0..n) Incident (Users report incidents)
- Admin (1) ←→ (0..n) Incident (Admins resolve incidents)
- Admin (1) ←→ (0..1) Admin_2 (Admin metadata)
