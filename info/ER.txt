ER Diagram - Lanka Transit (Updated with Simplified Extended Schema)

=== ORIGINAL TABLES ===

User
PK ID INT NOT NULL
Name VARCHAR(100) NOT NULL
Email VARCHAR(60) NOT NULL
PasswordHash VARCHAR(255) NOT NULL
PhoneNumber VARCHAR(10) NOT NULL
Role ENUM('administrator','guest user','registered user') NOT NULL
RegistrationDate TIMESTAMP DEFAULT CURRENT_TIMESTAMP

Booking
PK ID INT NOT NULL
FK UserId INT
FK BusID INT
SeatNumber VARCHAR(6) NOT NULL
BookingTime TIMESTAMP DEFAULT CURRENT TIMESTAMP
Status ENUM('confirmed','cancelled','completed') NOT NULL
PhoneNumber VARCHAR(10) NOT NULL
Fare DECIMAL(10,2) NOT NULL

Feedback
PK ID INT NOT NULL
FK UserId INT
FK BusId INT
Comment TEXT
Rating INT
CreatedDate DATE

Incident
PK ID INT NOT NULL
FK UserId INT
FK AdminId INT
FK BookingId INT
Description TEXT
Status ENUM('submitted','in progress','resolved') NOT NULL
ReportedDate DATE
ResolvedDate DATE

Admin
PK ID INT NOT NULL
Email VARCHAR(60) NOT NULL
PasswordHash VARCHAR(255) NOT NULL
Name VARCHAR(100) NOT NULL
PhoneNumber VARCHAR(10) NOT NULL

Bus
PK ID INT NOT NULL
FK RouteId INT
FK AdminId INT
BusNumber VARCHAR(7) NOT NULL
Capacity INT NOT NULL
LastUpdate DATE

Payment
PK ID INT NOT NULL
FK BookingId INT NOT NULL
PaymentMethod VARCHAR(50)
Status ENUM('success','failed') NOT NULL
Amount DECIMAL(10,2)
PaymentDate TIMESTAMP DEFAULT CURRENT_TIMESTAMP
TransactionId VARCHAR(100)

Receipt
PK ID INT NOT NULL
FK PaymentId INT NOT NULL
PdfUrl VARCHAR(255) NOT NULL
GeneratedDate DATE

Seat
PK ID INT NOT NULL
FK BusID INT
SeatNumber VARCHAR(6) NOT NULL
Status ENUM('available','booked')
GenderPreference ENUM('male','female','other') NOT NULL
IsLadySeat BOOLEAN

Schedule
PK ID INT NOT NULL
FK BusID INT
DepartureTime DATETIME NOT NULL
ArrivalTime DATETIME NOT NULL
Fare DECIMAL(10,2) NOT NULL

Route
PK ID INT NOT NULL
Origin VARCHAR(50)
Destination VARCHAR(50)
Stops TEXT

Location
PK UniqueID INT NOT NULL
Name VARCHAR(100) NOT NULL
Type ENUM('terminal','stop')

=== EXTENDED SCHEMA (schema2.sql) ===

Announcements
PK ID INT NOT NULL AUTO_INCREMENT
title VARCHAR(200) NOT NULL
message TEXT NOT NULL
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

=== RELATIONSHIPS ===

Original Relationships:
- A **User** makes a **Booking**
- A **Booking** reserves a **Seat**
- A **Booking** generates a **Payment**
- A **Payment** generates a **Receipt**
- A **User** submits a **Feedback**
- A **User** reports an **Incident**
- An **Admin** resolves an **Incident**
- An **Admin** manages a **Bus**
- A **Bus** contains many **Seats**
- A **Bus** has a **Schedule**
- A **Bus** operates on a **Route**
- A **Route** includes multiple **Locations**

Extended Relationships:
- **Announcements** is a standalone table for system notifications

=== SCHEMA2.SQL IMPLEMENTATION ===

**Purpose**: Adds only essential functionality that is actually implemented and used in the project.

**Content**: 
- Single **Announcements** table for system notifications
- Used in: admin/announcements.php and pages/announcements.php
- Simple design with title, message, and timestamps
- Includes sample data for testing

**Design Philosophy**:
- Minimal extension approach
- Only includes features that are actively used
- Avoids complex "_2" suffix table extensions
- Focuses on working functionality over theoretical completeness

**Future Extensions**:
- Additional tables can be added to schema2.sql as new features are implemented
- Each new table should be based on actual usage requirements
- Maintain simplicity and avoid unused attributes
