ER Diagram - Lanka Transit (Updated with Simplified Extended Schema)

=== ORIGINAL TABLES ===

User
PK ID INT NOT NULL
Name VARCHAR(100) NOT NULL
Email VARCHAR(60) NOT NULL
PasswordHash VARCHAR(255) NOT NULL
PhoneNumber VARCHAR(10) NOT NULL
Role ENUM('administrator','guest user','registered user') NOT NULL
RegistrationDate TIMESTAMP DEFAULT CURRENT_TIMESTAMP

Booking
PK ID INT NOT NULL
FK UserId INT
FK BusID INT
SeatNumber VARCHAR(6) NOT NULL
BookingTime TIMESTAMP DEFAULT CURRENT TIMESTAMP
Status ENUM('confirmed','cancelled','completed') NOT NULL
PhoneNumber VARCHAR(10) NOT NULL
Fare DECIMAL(10,2) NOT NULL

Feedback
PK ID INT NOT NULL
FK UserId INT
FK BusId INT
Comment TEXT
Rating INT
CreatedDate DATE

Incident
PK ID INT NOT NULL
FK UserId INT
FK AdminId INT
FK BookingId INT
FK RouteId INT
Description TEXT
Status ENUM('submitted','in progress','resolved') NOT NULL
ReportedDate DATE
ResolvedDate DATE

Admin
PK ID INT NOT NULL
Email VARCHAR(60) NOT NULL
PasswordHash VARCHAR(255) NOT NULL
Name VARCHAR(100) NOT NULL
PhoneNumber VARCHAR(10) NOT NULL

Bus
PK ID INT NOT NULL
FK RouteId INT
FK AdminId INT
BusNumber VARCHAR(7) NOT NULL
Capacity INT NOT NULL
LastUpdate DATE

Payment
PK ID INT NOT NULL
FK BookingId INT NOT NULL
PaymentMethod VARCHAR(50)
Status ENUM('success','failed') NOT NULL
Amount DECIMAL(10,2)
PaymentDate TIMESTAMP DEFAULT CURRENT_TIMESTAMP
TransactionId VARCHAR(100)

Receipt
PK ID INT NOT NULL
FK PaymentId INT NOT NULL
PdfUrl VARCHAR(255) NOT NULL
GeneratedDate DATE

Seat
PK ID INT NOT NULL
FK BusID INT
SeatNumber VARCHAR(6) NOT NULL
Status ENUM('available','booked')
GenderPreference ENUM('male','female','other') NOT NULL
IsLadySeat BOOLEAN

Schedule
PK ID INT NOT NULL
FK BusID INT
DepartureTime DATETIME NOT NULL
ArrivalTime DATETIME NOT NULL
Fare DECIMAL(10,2) NOT NULL

Route
PK ID INT NOT NULL
Origin VARCHAR(50)
Destination VARCHAR(50)
Stops TEXT

Location
PK UniqueID INT NOT NULL
Name VARCHAR(100) NOT NULL
Type ENUM('terminal','stop')

=== EXTENDED SCHEMA (schema2.sql) ===

User_2
PK user_id INT (FK to User.ID)
reset_token VARCHAR(255)
token_expiry DATETIME
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Booking_2
PK booking_id INT (FK to Booking.ID)
gender ENUM('male','female','undisclosed') DEFAULT 'undisclosed'
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Admin_2
PK admin_id INT (FK to Admin.ID)
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Announcements
PK ID INT NOT NULL AUTO_INCREMENT
title VARCHAR(200) NOT NULL
message TEXT NOT NULL
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

=== SCHEMA MODIFICATIONS (schema_3.sql) ===

**Incident Table Enhancement:**
- Added RouteId INT column with foreign key reference to Route(ID)
- Added index idx_incident_route for performance optimization
- Updated existing incident records to include route associations
- Enables route-specific incident tracking and analytics

=== RELATIONSHIPS ===

Original Relationships:
- A **User** makes a **Booking**
- A **Booking** reserves a **Seat**
- A **Booking** generates a **Payment**
- A **Payment** generates a **Receipt**
- A **User** submits a **Feedback**
- A **User** reports an **Incident**
- An **Admin** resolves an **Incident**
- An **Incident** is associated with a **Route**
- An **Admin** manages a **Bus**
- A **Bus** contains many **Seats**
- A **Bus** has a **Schedule**
- A **Bus** operates on a **Route**
- A **Route** includes multiple **Locations**

Extended Relationships:
- **User** extends to **User_2** (1:1 relationship) for password reset functionality
- **Booking** extends to **Booking_2** (1:1 relationship) for gender demographics
- **Admin** extends to **Admin_2** (1:1 relationship) for account tracking
- **Announcements** is a standalone table for system notifications

Schema 3 Enhancements:
- **Incident** now includes **RouteId** (Many:1 relationship with Route) for route-specific incident tracking

=== EXTENDED SCHEMA DETAILS ===

**User_2 Extensions:**
- reset_token: For secure password reset functionality
- token_expiry: Expiration time for reset tokens
- created_at: User account creation tracking

**Booking_2 Extensions:**
- gender: Passenger gender for analytics and seating preferences
- created_at: Booking creation tracking

**Admin_2 Extensions:**
- created_at: Admin account creation tracking

**Announcements:**
- Standalone table for system-wide notifications
- Used in admin/announcements.php and pages/announcements.php

**Indexes for Performance:**
- idx_user2_reset_token: Quick token lookups
- idx_user2_token_expiry: Token expiry validation
- idx_user2_created_at: User registration analytics
- idx_booking2_gender: Gender-based analytics
- idx_booking2_created_at: Booking date analytics
- idx_admin2_created_at: Admin account tracking
- idx_announcements_created_at: Announcement chronology
- idx_incident_route: Route-specific incident analytics and filtering

**Schema 3 Enhancements:**

**Incident Table RouteId Addition:**
- RouteId: Foreign key linking incidents to specific routes
- Enables route-specific incident tracking and analysis
- Supports route performance monitoring and maintenance planning
- Facilitates targeted route improvements based on incident patterns
- Allows for route-specific incident reporting and resolution tracking
