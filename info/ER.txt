ER Diagram - Lanka Transit Database Schema

=== CORE TABLES ===

User
PK ID INT AUTO_INCREMENT
Name VARCHAR(100) NOT NULL
Email VARCHAR(60) NOT NULL UNIQUE
PasswordHash VARCHAR(255) NOT NULL
PhoneNumber VARCHAR(10) NOT NULL
Role ENUM('administrator','guest user','registered user') NOT NULL DEFAULT 'registered user'
RegistrationDate TIMESTAMP DEFAULT CURRENT_TIMESTAMP

Booking
PK ID INT AUTO_INCREMENT
FK UserId INT (NULLABLE)
FK BusID INT NOT NULL
SeatNumber VARCHAR(6) NOT NULL
PhoneNumber VARCHAR(10) NOT NULL
Fare DECIMAL(10,2) NOT NULL
Status ENUM('confirmed','cancelled','completed') NOT NULL DEFAULT 'confirmed'
BookingTime TIMESTAMP DEFAULT CURRENT_TIMESTAMP

Feedback
PK ID INT AUTO_INCREMENT
FK UserId INT (NULLABLE)
FK BusId INT (NULLABLE)
FK BookingId INT (NULLABLE)
Comment TEXT
Rating INT (1-5)
CreatedDate DATE DEFAULT (CURRENT_DATE)

Incident
PK ID INT AUTO_INCREMENT
FK UserId INT (NULLABLE)
FK AdminId INT (NULLABLE)
FK BookingId INT (NULLABLE)
FK RouteId INT (NULLABLE)
Description TEXT
Status ENUM('submitted','in progress','resolved') NOT NULL DEFAULT 'submitted'
ReportedDate DATE DEFAULT (CURRENT_DATE)
ResolvedDate DATE (NULLABLE)

Admin
PK ID INT AUTO_INCREMENT
Email VARCHAR(60) NOT NULL UNIQUE
PasswordHash VARCHAR(255) NOT NULL
Name VARCHAR(100) NOT NULL
PhoneNumber VARCHAR(10) NOT NULL

Bus
PK ID INT AUTO_INCREMENT
FK RouteId INT (NULLABLE)
FK AdminId INT (NULLABLE)
BusNumber VARCHAR(7) NOT NULL UNIQUE
Capacity INT NOT NULL CHECK (Capacity IN (49, 54))
LastUpdate DATE
CONSTRAINT chk_bus_capacity: Capacity limited to 49 or 54 seats

Payment
PK ID INT AUTO_INCREMENT
FK BookingId INT NOT NULL
PaymentMethod VARCHAR(50)
Status ENUM('success','failed') NOT NULL
Amount DECIMAL(10,2) NOT NULL
PaymentDate TIMESTAMP DEFAULT CURRENT_TIMESTAMP
TransactionId VARCHAR(100)

Seat
PK ID INT AUTO_INCREMENT
FK BusID INT NOT NULL
SeatNumber VARCHAR(6) NOT NULL
Status ENUM('available','booked') DEFAULT 'available'
GenderPreference ENUM('male','female','other') NOT NULL
IsLadySeat BOOLEAN DEFAULT FALSE
UNIQUE KEY unique_seat_per_bus (BusID, SeatNumber)

BookingCancellation
PK ID INT AUTO_INCREMENT
FK BookingID INT NOT NULL
FK UserID INT (NULLABLE)
CancellationReason TEXT NOT NULL
RequestedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP
Status ENUM('pending','refunded','declined') NOT NULL DEFAULT 'pending'
FK ProcessedBy INT (NULLABLE)
ProcessedAt TIMESTAMP (NULLABLE)

Route
PK ID INT AUTO_INCREMENT
Origin VARCHAR(50) NOT NULL
Destination VARCHAR(50) NOT NULL
Stops TEXT (NULLABLE)

Location
PK UniqueID INT AUTO_INCREMENT
Name VARCHAR(100) NOT NULL
Type ENUM('terminal','stop') NOT NULL

Schedule
PK ID INT AUTO_INCREMENT
FK BusID INT NOT NULL
DepartureTime DATETIME NOT NULL
ArrivalTime DATETIME NOT NULL
Fare DECIMAL(10,2) NOT NULL

User_2
PK user_id INT (FK to User.ID)
reset_token VARCHAR(255) (NULLABLE)
token_expiry DATETIME (NULLABLE)
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Booking_2
PK booking_id INT (FK to Booking.ID)
gender ENUM('male','female','undisclosed') DEFAULT 'undisclosed'
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Admin_2
PK admin_id INT (FK to Admin.ID)
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Announcements
PK ID INT AUTO_INCREMENT
title VARCHAR(200) NOT NULL
message TEXT NOT NULL
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

=== RELATIONSHIPS ===

**Core Entity Relationships:**
- User (1) ←→ (0..n) Booking
- User (1) ←→ (0..n) Feedback  
- User (1) ←→ (0..n) Incident
- User (1) ←→ (0..n) BookingCancellation
- User (1) ←→ (0..1) User_2

- Admin (1) ←→ (0..n) Bus
- Admin (1) ←→ (0..n) Incident
- Admin (1) ←→ (0..n) BookingCancellation
- Admin (1) ←→ (0..1) Admin_2

- Route (1) ←→ (0..n) Bus
- Route (1) ←→ (0..n) Incident

- Bus (1) ←→ (0..n) Booking
- Bus (1) ←→ (0..n) Seat
- Bus (1) ←→ (0..n) Schedule
- Bus (1) ←→ (0..n) Feedback

- Booking (1) ←→ (1) Payment
- Booking (1) ←→ (0..n) BookingCancellation
- Booking (1) ←→ (0..n) Feedback
- Booking (1) ←→ (0..1) Booking_2


**Foreign Key Constraints:**
- CASCADE DELETE: Bus→Schedule, Bus→Seat, Booking→Payment, Payment→Receipt
- SET NULL: User/Admin references (maintains historical data)
- NULLABLE foreign keys support guest bookings and optional relationships
